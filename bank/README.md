# Банк Erachain

Мобильное приложение (Android APK) и веб-кабинет для работы с платформой
[Erachain](https://github.com/icreator/Erachain_public): счета и переводы, выпуск активов,
голосования, биржа, подпись документов, персоны и интеграция с банковскими системами —
всё в одном месте.

```
Android-приложение / браузер ──HTTPS──> сервер банка (bank/server.js) ──RPC──> нода Erachain
                                              │
                                              └── выписки 1С / ISO 20022, шлюз ввода-вывода, вебхук банка
```

Ключи хранятся в кошельке вашей ноды Erachain. Сервер банка — тонкий шлюз (Node.js ≥ 18,
без внешних зависимостей): проверяет данные, держит сессии и пароль кошелька только в памяти,
пропускает к ноде лишь нужные методы и добавляет банковскую интеграцию.

| Раздел | Возможности | Методы ноды |
|---|---|---|
| Главная | сводный баланс, счета, балансы по активам и позициям (собственность, долг, хранение), новый счёт, «получить» | `addresses`, `addresses/assets`, `addresses/new` |

| Голосования | список, результаты по вариантам (вес — баланс ERA/COMPU, число персон), голосование, создание | `polls/*`, `polls/issue`, `polls/vote` |

| Сообщения | телеграммы между счетами, шифрование | `telegrams/*` |

| Приём по СБП | QR-код СБП (банк «Точка») для оплаты рублями из любого банка, начисление актива Erachain по курсу, страница оплаты `pay.html` для клиентов | API СБП «Точки», `r_send` |
| Счета на оплату | «Безопасный платёж»: магазины выставляют счета на телефон клиента, банк находит и оплачивает их, уведомляет магазин | `telegrams/*`, `r_send` |
| Кредиты | договор, график (аннуитет/дифференцированный), выдача в долг в блокчейне, погашения, неустойка, взыскание | `r_send` с отрицательным номером актива и `backward`, `r_note`, `r_vouch` |
| Сотрудники | роли (администратор, операционист, бухгалтер, наблюдатель), смена, журнал действий | — |
| Обмен 7Pay | BTC, LTC, DOGE, DASH, ETH и др. ⇄ ERA, COMPU, токены через обменник [7Pay](https://github.com/icreator/7pay_in); оплата активами Erachain со счёта в одно касание; QR-код оплаты; курсы; отслеживание платежа; проверка лимитов | API `apipay`, `api/rates3` |
| Банк | выписки, поступления из банка, вывод в банк, настройки шлюза | см. ниже |
| Сеть | версия ноды, состояние, высота, последний блок | `core/*`, `blocks/*`, `peers` |

> **персонализированного** счёта — удостоверенного за персоной. Нода вернёт ошибку
> «Creator Account is not personalized», приложение покажет её как есть.

## Интеграция с банковскими системами

**Выписки** по любому счёту и активу за период:
- **1С** — `1CClientBankExchange` 1.03 в Windows-1251, загружается в 1С:Бухгалтерию через «Банк и касса → Обмен с банком»;
- **ISO 20022 camt.053** — XML-выписка для банков и ERP;
- **CSV** — для Excel и Google Таблиц.

**Шлюз «деньги ⇄ токен»** — для организации, выпускающей токен, обеспеченный деньгами на расчётном счёте
(например, «цифровой рубль»):

1. *Ввод.* Клиент платит на расчётный счёт организации и пишет в назначении свой адрес Erachain.
   Оператор загружает выписку банка (1С или ISO 20022 camt.053/camt.054) или банк присылает вебхук.
   Приложение находит поступления, извлекает адрес; оператор подтверждает зачисление, и токены
   переводятся со счёта шлюза клиенту. Повторная загрузка той же выписки не создаёт дублей,
   двойное зачисление заблокировано.
2. *Вывод.* Клиент переводит токены на счёт шлюза с сообщением
   `ВЫВОД;Получатель;ИНН;Счёт(20 цифр);БИК` (или JSON с полями `name, inn, account, bic`).
   «Проверить новые заявки» находит **подтверждённые** переводы и проверяет реквизиты.
   Заявки выгружаются в **платёжные поручения 1С** или **ISO 20022 pain.001**; после оплаты банком
   заявку отмечают оплаченной, ошибочную — возвращают (токены уходят отправителю).

**Вебхук банка:** `POST /api/bank/webhook`, заголовок `X-Signature: sha256=<HMAC-SHA256(тело, BANK_WEBHOOK_SECRET)>`,
тело — `{"id","date","amount","currency","payer","purpose"}` или массив. Поступления из вебхука ждут
подтверждения оператора: сервер не хранит пароль кошелька и не зачисляет токены сам.

Данные шлюза хранятся в `bank/data/gateway.json` (каталог задаётся `DATA_DIR`).

## Приём платежей по СБП

По образцу сервиса [era-polza-sbp](https://gitlab.com/erachain/era-polza-sbp) (приём паевых взносов по СБП с учётом в Erachain):

1. Клиент на странице **`/pay.html`** (без входа) или сотрудник в разделе «СБП → QR для клиента» указывает счёт
   Erachain, сумму в рублях и актив. Ссылку можно готовить заранее: `pay.html?to=АДРЕС&amount=550&asset=1048`.
2. Сервер регистрирует **динамический QR-код СБП** в банке «Точка» (`qrcType 02`) и показывает его вместе с
   кнопкой «Открыть в приложении банка».
3. Процессор каждые несколько секунд проверяет статусы оплат (`qr-codes/{ids}/payment-status`).
4. После оплаты сумма пересчитывается по курсу из настроек (рублей за 1 единицу актива) и актив переводится
   клиенту со **счёта выплат** — автоматически, пока открыта смена.

Статусы как в era-polza-sbp: ожидает оплаты → оплачен → в очереди → отправлено → начислено (или `FAIL_*` с
причиной для разбора). Защита денег:
- повторный запрос «тот же счёт + сумма + актив» в течение 12 минут возвращает тот же заказ;
- в сообщении каждой выплаты — метка `qrcId:trxId`; если сервер упал во время начисления, после перезапуска
  выплата находится по метке в истории счёта и **не повторяется**;
- неподтверждённая долго выплата не отправляется заново автоматически, а помечается для проверки;
- публичное создание QR ограничено 10 заказами за 10 минут с одного адреса.

Подключение «Точки» — только переменными окружения (в интерфейсе токен не хранится):
`TOCHKA_SBP_TOKEN`, `TOCHKA_MERCHANT` (ID торговой точки СБП), `TOCHKA_ACCOUNT` (расчётный счёт), `TOCHKA_BIK`,
`TOCHKA_MODE` = `test` (песочница) или `prod`. Регистрация юрлица и торговой точки в СБП делается один раз
в «Точке» (см. era-polza-sbp). Курсы, счёт выплат, минимальная сумма и срок QR — в «СБП → Настройки».

## Счета на оплату («Безопасный платёж»)

Протокол из [erachain-rpc](https://gitlab.com/erachain/erachain-rpc):

- **Магазин выставляет счёт** телеграммой на счёт-канал банка: заголовок — ID покупателя (телефон, e-mail или
  адрес), сообщение — JSON `{date, order, user, curr, sum, expire, title, description, details, callback}`.
- **Банк** по ID клиента находит его счета (фильтр телеграмм по заголовку), клиент оплачивает. Перевод магазину
  и уведомление `{"orderSignature", "curr", "sum"}` — **одна транзакция**; затем вызывается `callback` магазина
  с подписью транзакции (только https и только публичные адреса — защита от запросов во внутреннюю сеть).
- **Магазин** проверяет оплаты и засчитывает уведомления только от **доверенных банков** (из настроек),
  поддерживаются частичная оплата и счета без суммы (пополнение).
- Валюта счёта: ISO-код → актив Erachain по таблице (`643=1048` — рубль → «цифровой рубль»).

## Кредиты

Идея кредитного протокола из [icreator/protocol](https://github.com/icreator/protocol) (займы под процент),
реализованная средствами самой сети Erachain — **долговыми позициями баланса**:

| Действие | В блокчейне |
|---|---|
| Выдача | `r_send` с отрицательным номером актива — актив у заёмщика, долг учтён |
| Погашение | заёмщик переводит долг обратно (отрицательный номер актива) |
| Взыскание | кредитор забирает долг: отрицательный номер + `backward=true` |
| Договор | документ `r_note` с текстом и графиком, отправленный заёмщику; заёмщик заверяет его `r_vouch` |

Сервер ведёт график (аннуитетный или дифференцированный), считает просрочку и неустойку (% в день),
распределяет платёж: неустойка → проценты → тело; досрочное погашение снимает проценты полностью погашенных
периодов. Платежи, сделанные заёмщиком самостоятельно, находятся по номеру договора в заголовке перевода.

## Сид-фраза и вход

Сид-фраза — главный ключ банка: 32 случайных байта одной строкой Base58 (44 символа), как в кошельке Erachain —
её можно восстановить и в официальном кошельке. **Из одной фразы банк получает 21 счёт с приватными ключами**
(стандарт банка), ровно как нода Erachain:

- ключ счёта №n = SHA256(SHA256(n | сид | n)), n — 4 байта, с нуля; приватный ключ счёта — его Base58 (44 символа);
- пара ключей — Ed25519 из ключа счёта; адрес — Base58(15 | RIPEMD160(SHA256(публичный ключ)) | контрольная сумма).
  RIPEMD160 у ноды нестандартный (байты ≥ 0x80 расширяются знаком), поэтому `lib/erakeys.js` повторяет его
  один в один; адреса сверены с нодой (`addresses`, `addresses/makepairbyaccountseed`).

**Логика доступа:**

1. **Первый запуск.** На ноде нет кошелька — приложение открывает мастер: «Создать новый банк» (фраза
   генерируется и показывается один раз → проверка трёх случайных фрагментов «символы 9–12» → пароль
   кошелька; нода создаёт кошелёк сразу с 21 счётом) или «Восстановить по сид-фразе». Кто прошёл мастер — **владелец**. Чтобы посторонний не
   опередил владельца, сервер требует **код первого запуска**: он печатается в консоли сервера при старте
   (или задаётся `BANK_SETUP_CODE`).
2. **Владелец входит сид-фразой** (вкладка «Владелец»). Открывается экран «Ключи и кабинеты»: 21 счёт фразы
   с остатками и приватными ключами. Любой счёт можно выбрать для входа в его **кабинет** — тогда приложение
   показывает и подписывает только этот счёт («Сменить» — вернуться к списку). Если в кошельке ноды меньше
   21 счёта, недостающие открываются автоматически. Запасной вход — паролем кошелька.
3. **Вход по ключу счёта** (вкладка «Ключ счёта»): приватный ключ одного из 21 счёта открывает кабинет только
   этого счёта — остатки, история, переводы, выписки, документы, голосования, биржа. Сервер проверяет каждый
   запрос: подпись только от этого счёта, чужие счета, сотрудники, шлюз, СБП, кредиты недоступны. Владелец может
   выдать ключ, например, руководителю филиала. Отключение входа по фразе закрывает и кабинеты по ключам.
4. **Сотрудники входят логином и паролем** (вкладка «Сотрудник»), права — по роли. Сид-фразу они не видят
   и не вводят; подпись операций им даёт открытая смена.
5. **Настройки → Сид-фраза** (только владелец, каждый раз с паролем кошелька): показать фразу для резервной
   копии, включить вход по фразе (для банка, созданного раньше: вводится фраза с бумажной записи, сервер
   сверяет её с кошельком ноды), отключить вход по фразе.

**Как это устроено.** Сервер не хранит ни сид-фразу, ни ключи, ни пароль кошелька в открытом виде: он хранит
пароль кошелька, зашифрованный ключом из сид-фразы и отдельно — ключом каждого из 21 счёта (scrypt →
HMAC-SHA256 поток + HMAC-тег). Приватные ключи после входа фразой живут только в памяти сессии (15 минут). Без фразы расшифровать
его нельзя, а с ней владелец войдёт, даже если забыл пароль. На устройстве ничего не сохраняется; в Android
запрещены скриншоты и запись экрана (`FLAG_SECURE`). В журнал попадают вход и просмотр фразы, но не сама фраза.

## Регистрация клиентов

На экране входа две вкладки: **«Вход»** (сид-фраза, ключ счёта или логин сотрудника) и **«Регистрация»**.

1. **«Создать счёт»** — сервер генерирует новую сид-фразу (44 символа Base58) и её 21 счёт с приватными ключами.
   Кнопки: **«Скачать файлом»** (текстовый файл с фразой, основным счётом и 21 ключом: Android — в
   «Документы/Erachain», браузер — в «Загрузки»), **«Сохранить»** (системное «Поделиться»: Google Диск,
   Telegram, почта, «Файлы») и **«Копировать фразу»**. Ниже — список всех 21 счёта и ключей.
2. Отметка «Я сохранил(а) сид-фразу» → **«Зарегистрироваться и войти»**: 21 ключ импортируется в кошелёк ноды
   (`addresses/importaccountseed`), клиент сразу попадает на экран «Ключи и кабинеты».
3. Можно подключить и **свою фразу Erachain** («У меня уже есть сид-фраза Erachain»).

Клиент потом входит **своей сид-фразой** (или ключом одного счёта) и видит только свои 21 счёт: остатки,
переводы, история, выписки, документы, голосования, биржа. Чужие счета, сотрудники, шлюз, СБП и кредиты ему
недоступны — сервер проверяет каждый запрос. Банк не хранит ни фраз, ни ключей клиентов — только пароль кошелька,
зашифрованный ключом из фразы клиента и ключами его счетов. Новому клиенту можно начислить немного COMPU на
комиссии сети с первого счёта банка (`BANK_WELCOME_COMPU`, в демо — 0,01). Регистрация работает, пока открыта
смена (серверу нужен пароль кошелька, чтобы добавить ключи). Сотрудники видят клиентов в «Сотрудники →
Клиенты» и могут приостановить доступ клиента.

## Сотрудники, роли и смена

Сотрудники входят **своим логином и паролем** (хранятся как хеши scrypt), пароль кошелька им не нужен.

| Роль | Права |
|---|---|
| Владелец | всё, включая сид-фразу |
| Администратор | всё, кроме сид-фразы: операции, выписки, шлюз, настройки, сотрудники, смена, журнал |
| Операционист | переводы, обмен 7Pay, биржа, документы, выпуск, выписки, шлюз |
| Бухгалтер | просмотр, выписки, шлюз без подписи (загрузка выписок, выгрузка поручений, отметка оплаты) |
| Наблюдатель | только просмотр |

**Смена.** Администратор открывает смену (раздел «Сотрудники → Смена»): пароль кошелька проверяется нодой и
хранится только в памяти сервера банка. Пока смена открыта, сотрудники работают с кошельком; закрытие смены
или перезапуск сервера сразу отключают подписи. Отключённый или удалённый сотрудник теряет доступ немедленно.

**Журнал действий.** Каждое действие (кроме просмотра) и каждая попытка входа записываются: кто, роль, IP,
что сделано, ключевые поля (суммы, адреса, назначение) и результат. Пароли, файлы и фото в журнал не попадают.

Права проверяет сервер на каждом запросе — скрытые кнопки в интерфейсе лишь для удобства.

## Обменник 7Pay

Раздел «Обмен 7Pay» подключает обменник [7Pay](https://github.com/icreator/7pay_in) через его публичное API
`apipay` (сделка «to COIN»):

1. Выберите, что отдаёте и что получаете, и сумму с любой стороны — курс, доступный остаток и минимум
   считает обменник (`get_rate`, `get_rate_out`, `get_currs`).
2. Укажите, куда получить: для активов Erachain — счёт кошелька, для BTC и других — адрес кошелька.
3. «Создать заявку» (`get_uri_in` / `get_uri`) возвращает адрес обменника для оплаты.
   - **Отдаёте актив Erachain (ERA, COMPU, токен)** — кнопка «Оплатить с моего счёта»: сервер банка
     переводит актив на счёт 7Pay, а в заголовке перевода пишет `addr_out_full`
     (например `BTC:1Boat…`) — по нему 7Pay определяет, куда выплатить.
   - **Отдаёте BTC и др.** — приложение показывает адрес и сумму, ссылку «Открыть в кошельке» (URI).
4. «Проверить статус» (`history`) показывает платежи: ждут подтверждения → получен → выплата отправлена → выплачено,
   с суммой выплаты, комиссией и хешами транзакций.

Также: **QR-код** адреса оплаты (и адреса счёта в «Получить»), вкладка **«Курсы»** (средние курсы в BTC, USD, RUB из
`api/rates3`, по ним на главной показывается оценка ERA и COMPU в рублях и долларах), вкладка **«Отследить»** —
поиск платежей по валюте и адресу получения, даже если заявка создана не в приложении, и **проверка лимитов**
до создания заявки: минимум, остаток обменника, сколько он готов принять. Эти функции перенесены из клиента
обменника [Face2Face](https://github.com/icreator/f2f).

Адрес обменника задаётся переменной `SEVENPAY_URL` (по умолчанию `https://7pay.in`, `off` — выключить раздел).
Заявки хранятся в `bank/data/gateway.json`.

## Android-приложение (APK)

Приложение собирается из того же интерфейса (`bank/public`) с помощью Capacitor 8.

**Готовый APK** собирает GitHub Actions (`.github/workflows/bank-android.yml`) при каждом изменении
`bank/`: вкладка **Actions → «Банк Erachain — Android APK» → артефакт `erachain-bank-apk`**.
Для тега `bank-v1.0.0` APK публикуется в Releases.

**Сборка вручную** (нужны Android Studio / Android SDK и JDK 21):

```bash
cd bank
npm ci
npx cap sync android
cd android && ./gradlew assembleDebug   # app/build/outputs/apk/debug/app-debug.apk
```

При первом запуске приложение спросит адрес сервера банка (например, `https://bank.example.ru`
или `http://192.168.1.10:8080` в локальной сети). Выписки и платёжные поручения сохраняются через
системное меню «Поделиться» (почта, диск, мессенджеры, 1С).

### С нодой Erachain

1. Запустите ноду с включённым RPC без GUI (иначе нода спрашивает подтверждение каждого вызова в окне):
   `java -jar erachain.jar -nogui -rpc=on -rpcallowed=127.0.0.1`.
   Порт RPC: основная сеть — `9048`, тестовая (`-testnet`) — `9068`. Кошелёк заранее создавать не нужно —
   его создаст мастер первого запуска в приложении.
2. Запустите сервер банка рядом с нодой и запишите **код первого запуска** из консоли:

```bash
cd bank
ERA_RPC=http://127.0.0.1:9048 HOST=0.0.0.0 TLS_CERT=cert.pem TLS_KEY=key.pem npm start
```

## Безопасность

- Пароль кошелька живёт только в памяти сервера банка (сессия 15 минут бездействия); на устройство не сохраняется.
- Подбор пароля ограничен: после 5 ошибок вход блокируется с растущей задержкой.
- RPC ноды не открывайте наружу — точка входа только сервер банка. Для доступа из интернета включайте HTTPS.
- Приложение предупреждает, если адрес сервера вне локальной сети указан без HTTPS.
- Каждый перевод, выпуск, голос и подпись требуют подтверждения в интерфейсе.
- Вебхук принимает только запросы с верной HMAC-подписью.

## Исправления в ноде

Для работы приложения исправлены методы RPC ноды (`src/main/java/org/erachain`):
`assets/issue` (разбор `scale`/`assetType`), `polls/issue` и `polls/vote` (пароль, необязательный
`linkTo`, номер варианта, возврат ошибок), `polls/{key}` (результаты по вариантам), `r_note/make`
(список получателей, тестовый прогон, ответ с транзакцией), `persons/issue` (разбор чисел, дата смерти),
`trade/cancel` (отмена по номеру ордера SeqNo), `r_send` (флаг `backward` — взыскание долга; необязательный
`linkTo` в POST), новый метод `r_vouch/{creator}/{seqNo}` — заверение транзакции, `wallet` (состояние
кошелька без пароля, создание кошелька из сид-фразы без GUI), `wallet/seed?password=` (сид-фраза по паролю),
`addresses/importaccountseed?password=` (импорт счёта по приватному ключу без GUI).
