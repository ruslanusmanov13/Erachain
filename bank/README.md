# Банк Erachain

Мобильное приложение (Android APK) и веб-кабинет для работы с платформой
[Erachain](https://github.com/icreator/Erachain_public): счета и переводы, выпуск активов,
голосования, биржа, подпись документов, персоны и интеграция с банковскими системами —
всё в одном месте.

```
Android-приложение / браузер ──HTTPS──> сервер банка (bank/server.js) ──RPC──> нода Erachain
                                              │
                                              └── выписки 1С / ISO 20022, шлюз ввода-вывода, вебхук банка
```

Ключи хранятся в кошельке вашей ноды Erachain. Сервер банка — тонкий шлюз (Node.js ≥ 18,
без внешних зависимостей): проверяет данные, держит сессии и пароль кошелька только в памяти,
пропускает к ноде лишь нужные методы и добавляет банковскую интеграцию.

## Разделы приложения

| Раздел | Возможности | Методы ноды |
|---|---|---|
| Главная | сводный баланс, счета, балансы по активам и позициям (собственность, долг, хранение), новый счёт, «получить» | `addresses`, `addresses/assets`, `addresses/new` |
| Переводы | перевод любого актива с назначением и (шифрованным) сообщением; массовые выплаты из списка или CSV | `r_send` |
| История | все операции счёта, фильтр поступлений и списаний, подтверждения | `transactions/find`, `transactions/unconfirmedof` |
| Активы | портфель, каталог, карточка актива, **выпуск** токенов, акций, обязательств | `assets/*`, `assets/issue`, `assets/types` |
| Голосования | список, результаты по вариантам (вес — баланс ERA/COMPU, число персон), голосование, создание | `polls/*`, `polls/issue`, `polls/vote` |
| Биржа | любая пара активов, стакан, сделки, покупка и продажа, мои ордера, отмена | `trade/*` |
| Документы | подпись документа с текстом и файлами (в сеть уходит только SHA-256), получатели; проверка файла | `r_note/make`, `transactions/search` |
| Сообщения | телеграммы между счетами, шифрование | `telegrams/*` |
| Персоны | реестр, регистрация с фото, удостоверение ключа (персонализация счёта) | `persons/*`, `persons/certify` |
| Справочники | статусы и шаблоны документов | `statuses/*`, `templates/*` |
| Сотрудники | роли (администратор, операционист, бухгалтер, наблюдатель), смена, журнал действий | — |
| Обмен 7Pay | BTC, LTC, DOGE, DASH, ETH и др. ⇄ ERA, COMPU, токены через обменник [7Pay](https://github.com/icreator/7pay_in); оплата активами Erachain со счёта в одно касание; QR-код оплаты; курсы; отслеживание платежа; проверка лимитов | API `apipay`, `api/rates3` |
| Банк | выписки, поступления из банка, вывод в банк, настройки шлюза | см. ниже |
| Сеть | версия ноды, состояние, высота, последний блок | `core/*`, `blocks/*`, `peers` |

> В сети Erachain выпуск активов, голосований и регистрация персон доступны только с
> **персонализированного** счёта — удостоверенного за персоной. Нода вернёт ошибку
> «Creator Account is not personalized», приложение покажет её как есть.

## Интеграция с банковскими системами

**Выписки** по любому счёту и активу за период:
- **1С** — `1CClientBankExchange` 1.03 в Windows-1251, загружается в 1С:Бухгалтерию через «Банк и касса → Обмен с банком»;
- **ISO 20022 camt.053** — XML-выписка для банков и ERP;
- **CSV** — для Excel и Google Таблиц.

**Шлюз «деньги ⇄ токен»** — для организации, выпускающей токен, обеспеченный деньгами на расчётном счёте
(например, «цифровой рубль»):

1. *Ввод.* Клиент платит на расчётный счёт организации и пишет в назначении свой адрес Erachain.
   Оператор загружает выписку банка (1С или ISO 20022 camt.053/camt.054) или банк присылает вебхук.
   Приложение находит поступления, извлекает адрес; оператор подтверждает зачисление, и токены
   переводятся со счёта шлюза клиенту. Повторная загрузка той же выписки не создаёт дублей,
   двойное зачисление заблокировано.
2. *Вывод.* Клиент переводит токены на счёт шлюза с сообщением
   `ВЫВОД;Получатель;ИНН;Счёт(20 цифр);БИК` (или JSON с полями `name, inn, account, bic`).
   «Проверить новые заявки» находит **подтверждённые** переводы и проверяет реквизиты.
   Заявки выгружаются в **платёжные поручения 1С** или **ISO 20022 pain.001**; после оплаты банком
   заявку отмечают оплаченной, ошибочную — возвращают (токены уходят отправителю).

**Вебхук банка:** `POST /api/bank/webhook`, заголовок `X-Signature: sha256=<HMAC-SHA256(тело, BANK_WEBHOOK_SECRET)>`,
тело — `{"id","date","amount","currency","payer","purpose"}` или массив. Поступления из вебхука ждут
подтверждения оператора: сервер не хранит пароль кошелька и не зачисляет токены сам.

Данные шлюза хранятся в `bank/data/gateway.json` (каталог задаётся `DATA_DIR`).

## Сотрудники, роли и смена

Владелец входит **паролем кошелька** ноды (поле «Логин» пустое). Сотрудники входят **своим логином и паролем**
(хранятся как хеши scrypt), пароль кошелька им не нужен.

| Роль | Права |
|---|---|
| Владелец, Администратор | всё: операции, выписки, шлюз, настройки, сотрудники, смена, журнал |
| Операционист | переводы, обмен 7Pay, биржа, документы, выпуск, выписки, шлюз |
| Бухгалтер | просмотр, выписки, шлюз без подписи (загрузка выписок, выгрузка поручений, отметка оплаты) |
| Наблюдатель | только просмотр |

**Смена.** Администратор открывает смену (раздел «Сотрудники → Смена»): пароль кошелька проверяется нодой и
хранится только в памяти сервера банка. Пока смена открыта, сотрудники работают с кошельком; закрытие смены
или перезапуск сервера сразу отключают подписи. Отключённый или удалённый сотрудник теряет доступ немедленно.

**Журнал действий.** Каждое действие (кроме просмотра) и каждая попытка входа записываются: кто, роль, IP,
что сделано, ключевые поля (суммы, адреса, назначение) и результат. Пароли, файлы и фото в журнал не попадают.

Права проверяет сервер на каждом запросе — скрытые кнопки в интерфейсе лишь для удобства.

## Обменник 7Pay

Раздел «Обмен 7Pay» подключает обменник [7Pay](https://github.com/icreator/7pay_in) через его публичное API
`apipay` (сделка «to COIN»):

1. Выберите, что отдаёте и что получаете, и сумму с любой стороны — курс, доступный остаток и минимум
   считает обменник (`get_rate`, `get_rate_out`, `get_currs`).
2. Укажите, куда получить: для активов Erachain — счёт кошелька, для BTC и других — адрес кошелька.
3. «Создать заявку» (`get_uri_in` / `get_uri`) возвращает адрес обменника для оплаты.
   - **Отдаёте актив Erachain (ERA, COMPU, токен)** — кнопка «Оплатить с моего счёта»: сервер банка
     переводит актив на счёт 7Pay, а в заголовке перевода пишет `addr_out_full`
     (например `BTC:1Boat…`) — по нему 7Pay определяет, куда выплатить.
   - **Отдаёте BTC и др.** — приложение показывает адрес и сумму, ссылку «Открыть в кошельке» (URI).
4. «Проверить статус» (`history`) показывает платежи: ждут подтверждения → получен → выплата отправлена → выплачено,
   с суммой выплаты, комиссией и хешами транзакций.

Также: **QR-код** адреса оплаты (и адреса счёта в «Получить»), вкладка **«Курсы»** (средние курсы в BTC, USD, RUB из
`api/rates3`, по ним на главной показывается оценка ERA и COMPU в рублях и долларах), вкладка **«Отследить»** —
поиск платежей по валюте и адресу получения, даже если заявка создана не в приложении, и **проверка лимитов**
до создания заявки: минимум, остаток обменника, сколько он готов принять. Эти функции перенесены из клиента
обменника [Face2Face](https://github.com/icreator/f2f).

Адрес обменника задаётся переменной `SEVENPAY_URL` (по умолчанию `https://7pay.in`, `off` — выключить раздел).
Заявки хранятся в `bank/data/gateway.json`.

## Android-приложение (APK)

Приложение собирается из того же интерфейса (`bank/public`) с помощью Capacitor 8.

**Готовый APK** собирает GitHub Actions (`.github/workflows/bank-android.yml`) при каждом изменении
`bank/`: вкладка **Actions → «Банк Erachain — Android APK» → артефакт `erachain-bank-apk`**.
Для тега `bank-v1.0.0` APK публикуется в Releases.

**Сборка вручную** (нужны Android Studio / Android SDK и JDK 21):

```bash
cd bank
npm ci
npx cap sync android
cd android && ./gradlew assembleDebug   # app/build/outputs/apk/debug/app-debug.apk
```

При первом запуске приложение спросит адрес сервера банка (например, `https://bank.example.ru`
или `http://192.168.1.10:8080` в локальной сети). Выписки и платёжные поручения сохраняются через
системное меню «Поделиться» (почта, диск, мессенджеры, 1С).

## Запуск сервера

### Демо (без ноды)

```bash
cd bank
npm run demo          # http://127.0.0.1:8080, пароль: demo12345
```

Демо-режим имитирует ноду в памяти: счета, токен «цифровой рубль», голосование, биржа с ордерами,
персона, настроенный шлюз и заявка на вывод, обменник 7Pay, сотрудники `kassir` / `kassir123` (операционист)
и `buh` / `buh12345` (бухгалтер) с открытой сменой.

### С нодой Erachain

1. Запустите ноду с включённым RPC без GUI (иначе нода спрашивает подтверждение каждого вызова в окне):
   `java -jar erachain.jar -nogui -rpc=on -rpcallowed=127.0.0.1`.
   Порт RPC: основная сеть — `9048`, тестовая (`-testnet`) — `9068`.
2. Запустите сервер банка рядом с нодой:

```bash
cd bank
ERA_RPC=http://127.0.0.1:9048 HOST=0.0.0.0 TLS_CERT=cert.pem TLS_KEY=key.pem npm start
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ERA_RPC` | `http://127.0.0.1:9048` | адрес RPC ноды |
| `PORT` / `HOST` | `8080` / `127.0.0.1` | где слушать; `0.0.0.0` — для телефонов в сети |
| `TLS_CERT`, `TLS_KEY` | — | включить HTTPS |
| `DATA_DIR` | `bank/data` | данные шлюза |
| `BANK_WEBHOOK_SECRET` | — | секрет вебхука банка (без него вебхук выключен) |
| `SEVENPAY_URL` | `https://7pay.in` | адрес обменника 7Pay; `off` — выключить |
| `CORS_ORIGINS` | — | origin веб-клиентов на других доменах, через запятую |
| `BANK_DEMO` | — | `1` — демо-режим |

## Безопасность

- Пароль кошелька живёт только в памяти сервера банка (сессия 15 минут бездействия); на устройство не сохраняется.
- Подбор пароля ограничен: после 5 ошибок вход блокируется с растущей задержкой.
- RPC ноды не открывайте наружу — точка входа только сервер банка. Для доступа из интернета включайте HTTPS.
- Приложение предупреждает, если адрес сервера вне локальной сети указан без HTTPS.
- Каждый перевод, выпуск, голос и подпись требуют подтверждения в интерфейсе.
- Вебхук принимает только запросы с верной HMAC-подписью.

## Исправления в ноде

Для работы приложения исправлены методы RPC ноды (`src/main/java/org/erachain`):
`assets/issue` (разбор `scale`/`assetType`), `polls/issue` и `polls/vote` (пароль, необязательный
`linkTo`, номер варианта, возврат ошибок), `polls/{key}` (результаты по вариантам), `r_note/make`
(список получателей, тестовый прогон, ответ с транзакцией), `persons/issue` (разбор чисел, дата смерти),
`trade/cancel` (отмена по номеру ордера SeqNo).
